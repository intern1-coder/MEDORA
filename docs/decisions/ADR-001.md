# ADR-001: Architectural Baseline and Approved Technology Stack

## Context
Medora requires a reliable, scalable, type-safe, and maintainable backend architecture to manage hospital operations, patient records, queue allocations, clinical consultations, and billing. As an enterprise healthcare system handling patient identifiable and sensitive medical data, strict data integrity, concurrency management, and modular software boundaries are paramount.

## Decision
We adopt the approved technology stack and clean layered architecture:
1. **Language & Runtime**: Node.js with TypeScript (`strict: true`) to ensure compile-time type safety across domain entities, request payloads, and service interfaces.
2. **Web Framework**: Express.js with a modular routing, middleware, controller, and service layer separation.
3. **Database & ORM**: PostgreSQL engine with Prisma ORM for relational schema modeling, migrations, and type-safe query generation.
4. **Validation**: Zod for compile-time and runtime validation of all inbound HTTP requests (body, params, query).
5. **Testing**: Jest and Supertest for unit, integration, and RBAC authorization test suites.
6. **API Specification**: OpenAPI 3.0 / Swagger UI for standardized interactive API contracts.
7. **Containerization**: Docker and Docker Compose for local PostgreSQL database and Redis/dependency orchestration.

## Consequences
- **Positive**:
  - Full type safety from database models (Prisma) to business services and HTTP DTOs (Zod).
  - Clean separation prevents business logic leakage into controllers or routes.
  - Predictable relational database operations with ACID guarantees critical for appointment slots and billing.
  - Deterministic automated testing pipeline.
- **Negative / Trade-offs**:
  - Requires disciplined maintenance of Zod schemas and Prisma models in synchronization.
  - Layered structure requires deliberate file organization rather than ad-hoc scripting.
