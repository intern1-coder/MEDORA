# ADR-004: Concurrency-Safe Patient Medical Record Number (MRN) Strategy

## Status
- **MRN Visible Format**: **OWNER APPROVED** (`MED-YYYY-XXXXX`).
- **Runtime Implementation**: **NOT IMPLEMENTED** (No code written yet).
- **Annual Reset & Overflow Policies**: **UNRESOLVED / PROPOSED** (Comparative analysis presented below).

## Context
Every patient registered in Medora requires a unique, human-readable, and sequential Medical Record Number (MRN). The approved format is:
`MED-YYYY-XXXXX`
where:
- `MED`: Medora system prefix.
- `YYYY`: Registration calendar year (4 digits, e.g. `2026`).
- `XXXXX`: Zero-padded 5-digit sequential integer (`00001` through `99999`).

Because hospital reception desks may register multiple walk-in and scheduled patients simultaneously across multiple terminals, generating this sequence naively introduces race conditions and duplicate key errors under high concurrency.

---

## 1. Concurrency-Safe Generation Strategy [PROPOSED]
To guarantee sequential continuity without race conditions or gap risks during high concurrency, MRN generation executes within an atomic database transaction using row-level locking on a dedicated counter table:
```sql
CREATE TABLE mrn_sequences (
    year INT PRIMARY KEY,
    current_value INT NOT NULL DEFAULT 0,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Concurrency-safe atomic increment:
INSERT INTO mrn_sequences (year, current_value, updated_at)
VALUES ($current_year, 1, NOW())
ON CONFLICT (year)
DO UPDATE SET
    current_value = mrn_sequences.current_value + 1,
    updated_at = NOW()
RETURNING current_value;
```
- PostgreSQL row-level locks on the specific year's record guarantee that concurrent receptionist registrations queue deterministically for microseconds, fetch unique numbers, and never collide.
- The `patients` table maintains a database-level unique constraint: `CREATE UNIQUE INDEX idx_patients_mrn ON patients (mrn);`.

## 2. Policy Comparisons & Trade-offs [UNRESOLVED]

### 2.1 DEC-004A: Annual Sequence Reset Options

| Policy Option | Operational Behavior | Database & Uniqueness Impact | Registration Workflow Impact |
| :--- | :--- | :--- | :--- |
| **Option 1: Annual Reset at Local Midnight (Hospital Timezone)** | Sequence restarts at `00001` at 00:00:00 on January 1st in the hospital's configured timezone (`MED-2026-00001`, `MED-2027-00001`). | - Uniqueness enforced by composite tuple `(year, current_value)`.<br>- Natural partitioning by annual patient cohorts.<br>- Sequence table keys directly by `year`. | - Predictable, human-readable numbers for receptionists.<br>- Annual intake volume immediately obvious from MRN suffix. |
| **Option 2: Continuous Global Sequence Across Years** | Sequence monotonically increases indefinitely across years (`MED-2026-00001` ... `MED-2027-01542`). | - Global sequence across all time.<br>- Uniqueness guaranteed solely by monotonic integer.<br>- Year in prefix reflects only registration year, not sequence baseline. | - Receptionists see continuously growing numbers.<br>- No dependency on midnight timezone transitions.<br>- Reaches 5-digit limit faster. |

**Engineering Analysis**: Option 1 is standard in clinical outpatient systems because annual cohorts keep numbers manageable and clinically organized. Timezone alignment must be locked to the hospital's local timezone (e.g., `Asia/Kolkata` or local time) rather than unadjusted UTC to prevent cohort rollovers mid-shift.

---

### 2.2 DEC-004B: Five-Digit Limit and Overflow Behavior

| Policy Option | Operational Behavior | Database & Uniqueness Impact | Registration Workflow Impact |
| :--- | :--- | :--- | :--- |
| **Option 1: Enforce Strict 5-Digit Cap (Max 99,999)** | Hard ceiling at 99,999. Automated administrative warning fires at 90,000. Registration halts if 99,999 is exceeded in a single year. | - Guaranteed fixed-width `VARCHAR(14)` string.<br>- Strict compliance with `MED-YYYY-XXXXX` format.<br>- Zero database schema adjustments. | - If volume unexpectedly exceeds 99,999 in a single year, reception registrations halt until administrative intervention.<br>- High-volume hospital networks could face intake blockage. |
| **Option 2: Dynamic Sequence Expansion (Beyond 99,999)** | Sequence naturally expands to 6 digits (`MED-2026-100000`) if registrations exceed 99,999. | - Column must be sized as `VARCHAR(32)` to accommodate expansion.<br>- Modifies strict 5-digit format definition for overflow cases. | - Zero risk of patient intake blockage.<br>- Seamless continuation during massive epidemic or high-volume surge. |

**Engineering Analysis**: Setting the database column width to `VARCHAR(32)` allows Option 2 without breaking database constraints. If the owner strictly requires 5 digits, Option 1 with a high-priority threshold alert (at 90,000) provides strict format adherence.
